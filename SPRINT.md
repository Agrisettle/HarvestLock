# 7-Day Sprint — get this contributor-ready

**Start:** 1 Sept 2026 &nbsp;|&nbsp; **Target:** 8 Sept 2026 &nbsp;|&nbsp; **Goal:** a stranger can clone this, run it, understand it, and pick up real work — not "the product is finished."

This is a tactical, week-scoped plan layered on top of `ROADMAP.md`'s Phase 0/1. `ROADMAP.md` doesn't change; this file expires after day 7 and gets archived once its job is done. `HANDOFF.md` is the living source of truth for *current state* — this file is the plan, HANDOFF.md is the reality, and they will drift as the week goes. Trust HANDOFF.md when they disagree.

## What "ready for contributors" actually means here

Not "feature-complete." It means: the repo builds and tests pass from a clean clone in under 10 minutes, the next 10 tasks are already written down as issues with enough context to start without asking, CI catches broken PRs automatically, and no contributor's first PR requires reverse-engineering undocumented decisions — HANDOFF.md and the component READMEs already carry that.

## Honest scope call

Fully building the API and both product frontends to the same rigor as the contracts work (real tests, testnet-verified, audited) is not a 7-day job for one contributor. Building all three shallowly, unaudited, would actively work against "contributor-ready" — new contributors inherit debt instead of a foundation. So the priority order is:

1. **Onboarding infrastructure** (this week's real deliverable) — CI, CONTRIBUTING.md, HANDOFF.md, filed issues with real context.
2. **The API** — real, tested, testnet-verified, because both frontends are blocked on it existing. This is the one component worth building deep rather than wide this week.
3. **coop-pwa and buyer-app** — a thin, honest read-only slice each if time allows; otherwise these become the first real contributor tasks, fully scoped as issues rather than half-started.

## Retro (filled in 17 Oct 2026 — the audit *was* day 7)

Written five weeks after the sprint window actually closed, which is itself the first retro finding: the sprint's day labels stopped matching reality early (Days 2-5 all landed on 1 Sept; the contract work that dominated the week lived mostly in the separate contracts repo). This file drifted into lying by omission — Day 3 was checked as undone for five weeks after it shipped — which is exactly the failure mode `HANDOFF.md`'s own preamble warns about. Lesson recorded where it'll be read: day-scoped checklists rot; component-scoped backlogs (`TASKS.md`) don't.

What went well, for real: the decision to build the API deep rather than three components shallowly held up — every frontend built later leaned on routes that already existed and were live-verified, so `warehouse-app` shipped with zero new API surface. The "verify against live testnet, not mocks" discipline caught real bugs no unit test would have (the `scValToNative` status-array one, and this audit's stale-constant one, found by actually running the live suite again). CI with real Postgres containers made the network-free half of `api`'s suite verifiable by anyone in minutes.

What the audit found: docs drift is the recurring cost of a fast-moving solo project. Four separate false "not built yet" claims across three files, all safe to write when written, all misleading by 17 Oct. The one genuine code-level finding was a test that had been deterministically broken for five weeks (a constant pointing at a contract whose struct the API had outgrown) — long enough that it had been informally written off as "testnet flakiness" in one place. Both now fixed, and the fixed test asserts the newest struct fields specifically so this rot can't hide again.

What genuinely slipped and stays open (matching `TASKS.md`, deliberately): the appeals process's actual reinstatement workflow, phone-based auth, ERP integration, and manual QA against a real installed Freighter extension. None of these is a sprint failure — all four were consciously deferred behind real prerequisites or real usage.

Sprint-goal honesty: "a stranger can clone this, run it, understand it, and pick up real work" is now true for everything in this checkout. The one place it needs a handhold is `api`'s live-testnet suite — which is why this audit wrote its exact reproduction values into `api/HANDOFF.md` rather than leaving them in a `.env` nobody can see.
